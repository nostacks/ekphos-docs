Ekphos supports YAML frontmatter for storing metadata in your notes. Frontmatter is the content between `---` delimiters at the very beginning of a file.

## Basic Format

```markdown
---
title: My Note Title
tags: [rust, cli, terminal]
date: 2024-01-15
author: Your Name
---

# Your Note Content

Regular markdown content starts here...
```

## Supported Fields

| Field | Type | Description |
|-------|------|-------------|
| `title` | string | Note title (optional) |
| `tags` | array | List of tags for categorization |
| `date` | string | Date associated with the note |
| `author` | string | Note author |
| *any* | any | Additional custom fields are preserved |

## Tag Badges

When a note has frontmatter with tags, they are displayed as visual badges at the top of the content view:

```
 rust   cli   terminal
─────────────────────────
# Your Note Content
...
```

Tags are styled with the theme's `tag` and `tag_background` colors.

<Callout>
Tag badges only appear when `show_tags = true` in your config (enabled by default).
</Callout>

## Frontmatter Visibility

By default, the raw frontmatter YAML is hidden in the content view to keep your notes clean. Only the tag badges are shown.

### Toggle Visibility

By default, press `Ctrl+m` while in the Content panel to toggle frontmatter
visibility. The shortcut is configurable as
[`toggle_frontmatter`](/docs/configuration#keybindings):

- **Hidden (default)**: Only tag badges shown, frontmatter lines hidden
- **Visible**: Full frontmatter displayed with syntax highlighting

When visible, frontmatter is rendered with:
- `---` delimiters in muted color
- Keys in info color (blue)
- Values in frontmatter color (muted)

<Callout>
In Edit mode, frontmatter is always visible as raw text for editing.
</Callout>

## Configuration

Add these options to your `config.toml`:

```toml title="config.toml"
[general]
# Hide frontmatter in content view (default: true)
frontmatter_hidden = true

# Show tag badges when note has tags (default: true)
show_tags = true
```

### Theme Colors

Customize frontmatter and tag colors in your theme file:

```toml title="themes/my-theme.toml"
[ui.content]
# Tag badge text color
tag = "#bb9af7"

# Tag badge background color
tag_background = "#24243a"

# Frontmatter key/value text color
frontmatter = "#565f89"
```

## Tags Format

Tags can be specified in YAML array format:

```yaml
# Inline array
tags: [rust, cli, terminal]

# Multi-line array
tags:
  - rust
  - cli
  - terminal
```

## Frontmatter Templates

Frontmatter templates add the same metadata to new notes automatically. Store
each template as a YAML fragment in `~/.config/ekphos/templates/`. Ekphos
creates this directory on startup. Leave out the `---` delimiters because
Ekphos adds them when it creates the note.

For example, create `~/.config/ekphos/templates/project.yaml`:

```yaml title="project.yaml"
title: "{{title}}"
created: "{{date}}"
folder: "{{folder}}"
tags: [project]
status: active
```

Then map vault folders to template files in `config.toml`:

```toml title="config.toml"
[frontmatter_templates]
"." = "default.yaml"
"Projects" = "project.yaml"
"Projects/Clients" = "client.yaml"
```

Folder keys are case-sensitive, use `/` separators, and are relative to the
vault. `.` represents the vault root. Template paths are relative to
`~/.config/ekphos/templates/` and must stay inside that directory.

Ekphos checks the note's destination folder first and then walks up through its
parents. The closest mapping wins. In the example above:

- A note in `Projects/Clients` uses `client.yaml`.
- A note in `Projects/Research` inherits `project.yaml`.
- A note outside `Projects` uses `default.yaml`.
- Without a matching folder or root mapping, the note keeps its normal
  heading-only content.

### Template Variables

Place variables inside quoted YAML string values:

| Variable | Value |
| --- | --- |
| `{{title}}` | New note name |
| `{{date}}` | Current local date in `YYYY-MM-DD` format |
| `{{folder}}` | Vault-relative destination folder, or `.` for the vault root |

Variables also work inside longer strings, such as
`summary: "Project note: {{title}}"`. Static arrays, numbers, booleans, and
custom properties remain valid YAML values.

<Callout>
  Ekphos parses and rewrites the YAML to keep generated frontmatter valid.
  Comments and formatting from the template are not copied into the new note.
</Callout>

### When Templates Apply

Templates apply to notes created from the New Note dialog and from missing
wiki links. They do not change existing notes, and [journal notes](/docs/journal)
keep their dedicated dated format.

Template files are read for every new note, so file edits apply immediately.
After changing `[frontmatter_templates]` in `config.toml`, press
`Ctrl+Shift+R` to reload the mappings.

<Callout type="warn">
  If a mapped template is missing, unreadable, invalid YAML, uses the wrong type
  for a supported field, or contains an unknown variable, Ekphos cancels note
  creation and shows the error. Fix the template or mapping, then create the
  note again.
</Callout>

## Examples

### Minimal Frontmatter

```markdown
---
tags: [notes]
---

# Quick Note

Just a simple note with one tag.
```

### Full Metadata

```markdown
---
title: Project Documentation
tags: [project, docs, important]
date: 2024-01-15
author: John Doe
status: draft
priority: high
---

# Project Documentation

This note has extensive metadata...
```

### No Frontmatter

Notes without frontmatter work normally - they simply won't display tag badges:

```markdown
# Regular Note

No frontmatter here, just content.
```

## Keybindings

| Key | Panel | Action |
|-----|-------|--------|
| `Ctrl+m` | Content | Toggle frontmatter visibility |

<Callout type="warn">
Invalid YAML frontmatter is silently ignored - the file will be treated as having no frontmatter. Make sure your YAML syntax is correct.
</Callout>
